# ServiceNow Integration

## Implementation choice
A **Power Automate flow** called as a Copilot Studio *Action*, using the **ServiceNow** connector (`Create Record`).
Recommended target table: a custom table `u_azure_subscription_request` (extending `sc_req_item`), or a catalogue Record Producer if you prefer to reuse an existing form.
Connection: a **service account** `svc-copilot-vending` (not every requester holds a ServiceNow ITIL licence). The real requester is carried by `requested_for`.

---

## Flow 1 — `SubmitToServiceNow`

**Inputs** (from Copilot Studio): all intake fields plus a serialised `Global.Derived`.

**Steps**
1. `Compose` — build the payload (below).
2. `ServiceNow — Create Record` on `u_azure_subscription_request`.
3. `Condition` — if `dataClassification = restricted` **or** `accessPersona = app-team-elevated` → `Update Record` with `u_approval_group = SEC-CLOUD-REVIEW`, otherwise `u_approval_group = CLOUD-PLATFORM-APPROVERS`.
4. `Response` → return `number` (RITM), `sys_id`, `u_approval_group`, `state`.

**Payload**

## Flow 2 — `GetServiceNowRecord`

`ServiceNow — Get Record` by `number`, **or** a query on `requested_for={upn}^active=true` (used by `ListMyRequests`).
Map the ServiceNow `state` to the business state:

| ServiceNow `state` | Agent state |
|---|---|
| `1` Open / `-5` Pending Approval | `pending_approval` |
| `2` Work in Progress + `u_pipeline_state=running` | `running` |
| `2` + `u_pipeline_state=failed` | `failed` |
| `3` Closed Complete | `completed` |
| `4` Closed Incomplete / Rejected | `rejected` |

Also return: `u_subscription_id`, `u_managed_identity_client_id`, `u_entra_group`, `u_pr_url`, `u_pipeline_step`, `u_reject_reason`, `approver`.

## Flow 3 — `TriggerDeployment` (post-approval)

Trigger: a **ServiceNow Business Rule** on `state → Approved` calling a webhook into Power Automate. (The agent may also run it on request, but only when the state it reads is `approved`.)

Steps:
1. **Guard rail**: re-read the record. If `state != approved` → **abort** and log. Never trust in-memory state.
2. Generate `azure.yml` from `u_derived_config`.
3. **GitHub** connector → `Create a pull request` on `{workzoneRepo}` (or `Dispatch workflow` / `repository_dispatch` if the repo prefers that).
   - Branch: `vending/{appId}-{environment}-{RITM}`
   - File: `.platform/subscriptions/{appId}-{environment}/azure.yml`
   - PR title: `[vending] {appId} {environment} — {RITM}`
   - Reviewers: platform team plus `owner.upn`
4. `Update Record` in ServiceNow: `u_pr_url`, `u_pipeline_state = pr_open`.
5. Proactive Teams notification to the requester.

**Key point**: the agent produces a **reviewed artifact** (a PR). It holds **no** write permission on Azure. The deterministic pipeline consumes the YAML and runs `avm/ptn/lz/sub-vending`.
