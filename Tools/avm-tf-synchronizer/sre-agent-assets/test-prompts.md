# 🧪 Demo runbook: AVM TF Synchronizer

> Step-by-step test of the agent on the Key Vault module, from vanilla `v1.0.0` to a synced and compliant `v2.0.0` in **one PR**.

| | |
|---|---|
| 📦 **Module** | [contoso/sre-agent-avm-keyvault-module-custom], `main` = vanilla `v1.0.0` (AVM `v0.10.2`) |
| 🔐 **Controls** | [contoso/sre-agent-avm-security-controls], `SC-KV-001` … `SC-KV-011` |
| 🌐 **Upstream** | `Azure/terraform-azurerm-avm-res-keyvault-vault`, latest `v0.12.0` |
| 🎯 **Expected outcome** | One PR `feat!: sync AVM v0.10.2 → v0.12.0 and enforce security controls` → release `v2.0.0` |

## 📑 Steps

1. [Check the starting state](#1-check-the-starting-state)
2. [Configure the agent](#2-configure-the-agent)
3. [Start a clean thread](#3-start-a-clean-thread)
4. [Run the test prompts](#4-run-the-test-prompts)
5. [Run the agent: sync and enforce controls in one PR](#5-run-the-agent-sync-and-enforce-controls-in-one-pr)
6. [Check the result](#6-check-the-result)

### 1. Check the starting state

- [ ] Module `main` is vanilla `v1.0.0`: `.avm-sync/manifest.yaml` has `last_synced_tag: v0.10.2`, and `mapping.yaml` has no `locked: true` entries.
- [ ] No open PRs on the module repo, and no `remediation/*` or `avm-sync/*` branches.
- [ ] The latest run of **PR format & validation** on `main` is green (Terraform `^1.11`).
- [ ] Repo variable `FMT_BOT_APP_ID` and secret `FMT_BOT_PRIVATE_KEY` exist (fmt autofix).

### 2. Configure the agent

- [ ] Paste the contents of [sre-agent-instructions.md](./sre-agent-instructions.md) into **AVM TF Synchronizer**.
- [ ] Set the `avm-release-watcher` scheduled task prompt to `Run COMPLIANCE, DETECTION, DECIDE and LIVE REPORT for contoso/sre-agent-avm-keyvault-module-custom.`.

> [!TIP]
> To drive the test from chat, **pause the scheduled task** first. Otherwise it may open the PR on its own within 6 hours.

### 3. Start a clean thread

Open a **new chat thread** so the agent starts without context from earlier conversations.

### 4. Run the test prompts

| # | Prompt | Expected result | What it checks |
|---|---|---|---|
| 1 | `List the files in contoso/sre-agent-avm-security-controls and contoso/sre-agent-avm-keyvault-module-custom.` | Files from both repos | The connector can see both repos |
| 2 | `What is the latest release of Azure/terraform-azurerm-avm-res-keyvault-vault?` | `v0.12.0` | The agent can read public repos |
| 3 | `Run COMPLIANCE only and report, without opening a PR.` | Most SC-KV controls **non-compliant**; SC-KV-006 and SC-KV-010 **not applicable**; SC-KV-007 compliant | Compliance evaluation |
| 4 | `Run PARITY for contoso/sre-agent-avm-keyvault-module-custom.` | At parity with `v0.10.2`; adapted and excluded items listed | The module matches its starting AVM version |

### 5. Run the agent: sync and enforce controls in one PR

1. In chat, ask:

   ```text
   Run COMPLIANCE, DETECTION, DECIDE and LIVE REPORT for contoso/sre-agent-avm-keyvault-module-custom.
   ```

   The agent should find most controls non-compliant on `main`, find `v0.10.2 → v0.12.0`, and open **one** PR on `avm-sync/v0.12.0`. It ends with a table: step | result | PR link or report link.
2. Wait for CI. If the fmt autofix pushes a `style: terraform fmt` commit, the next run validates it.
3. Review the PR:
   - [ ] Title is `feat!: sync AVM v0.10.2 → v0.12.0 and enforce security controls`, with no `[Generated by SRE Agent]` prefix.
   - [ ] Body is raw Markdown (no literal `\n`) with a **Changes** table and a **Security controls** table (status on `main` and on the branch).
   - [ ] Every upstream change is PORTED, PORTED with adaptation, or SKIPPED with a control ID.
   - [ ] No applicable control is left non-compliant. Every new lock is in `mapping.yaml` and has a test in `tests/basic.tftest.hcl`.
   - [ ] If AVM renamed an attribute that a control covers (for example the RBAC flag for SC-KV-011), the lock moved to the new name.
   - [ ] `last_synced_tag` is `v0.12.0`. `CHANGELOG.md`, `.release-please-manifest.json` and `.github/workflows/*` are untouched.
   - [ ] The body ends with a `BREAKING CHANGE:` footer, and all checks are green.
4. Squash-merge the PR.
5. release-please opens `chore(main): release 2.0.0`. Merge it to create the `v2.0.0` tag and release.

### 6. Check the result

| # | Action | Expected |
|---|---|---|
| 1 | Run the step 5 prompt again | **No action**: compliant and up to date. The Live Report is updated |
| 2 | `Run PARITY for contoso/sre-agent-avm-keyvault-module-custom.` | At parity with `v0.12.0`; locked controls shown as **adapted** |
| 3 | Open the Live Report **AVM TF Synchronizer – Activity** | The PR (merged), `v2.0.0`, `last_synced_tag v0.12.0` and the locked controls |

> [!NOTE]
> If the agent couldn't create the Live Report during a run, ask it once in chat: `Build the Live Report described in LIVE REPORT.`
