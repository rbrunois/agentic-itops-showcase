Why it matters

The problem it solves.

Platform teams fork Azure Verified Modules to add their own structure and security settings, then fall behind upstream. Porting each release by hand is slow, and it's easy to undo a security setting by accident.

  • Always current

    New AVM releases are ported into your module structure, with a port, adapt or skip decision per change.

  • Controls always win

    Every applicable security control is enforced on the result, in the same pull request as the upgrade.

  • People stay in control

    At most one pull request per run. CI validates it, and a human reviews and squash-merges it.

  • Clean releases

    release-please reads the merged PR title and creates the tag and changelog. The agent never does.

How it works

From trigger to approved change.

The same operating model as every use case in the showcase, applied to AVM TF Synchronizer.

  1. Trigger

    A scheduled run every six hours, or an on-demand prompt

  2. Analyze

    Checks every control, then diffs the latest AVM release against the module

  3. Approve

    One pull request waits for CI and a maintainer's review

  4. Apply

    The maintainer squash-merges; release-please creates the new version tag

      Is it for you?
      
      
      Who it helps and what it takes.
      
      
      
      
        
      Who it's for
      • Platform teams that publish internal Terraform modules
      • Security teams that own module controls
      
        
      What you need
      • An Azure SRE Agent with GitHub access to the module repository
      • A module forked from an Azure Verified Module
      • Security controls in a controls repository
      • .avm-sync/ manifest, mapping and exclusions files
      
      
      
      
      The value
      Demonstrates a guarded AVM-to-internal-module assessment with internal security controls without automatically applying a patch
