Azure SRE Agent — Camping Store

Connect the incident, the code, and the customer report.

Deploy a complete Camping Store and SRE Agent, investigate an approved memory fault, trace source code, and draft customer issue triage. People approve every change.

Why it matters

One workload, three SRE perspectives.

  • Operations

    Correlate cart traffic, retained analytics buffers, memory growth, and replica restarts.

  • Development

    Trace telemetry to included C# source and prepare an evidence-backed, review-only issue draft.

  • Customer support

    Classify synthetic reports and propose labels and comments without publishing automatically.

  • Self-contained onboarding

    The app, infrastructure, agent configuration, knowledge, and offline tests live together.

This complements Azure SRE Incident Response, which rehearses revision failure and captured-baseline recovery; it does not replace it.

How it works

Prepare, investigate, propose, approve.

  1. 1

    Prepare

    Review billable infrastructure, deploy the app, and onboard a read-only SRE Agent.

  2. 2

    Investigate

    Approve bounded demo load; correlate metrics, logs, and source code.

  3. 3

    Review

    Read the proposed recovery, root cause, and draft customer communication.

  4. 4

    Act separately

    An operator approves recovery and verifies cart/checkout, then cleans up.

      Safety and fit
      An isolated lab, not a production storefront.
      
    
      
      
      Read-only investigation
      The agent has resource-group Reader, Monitoring Reader, and Log Analytics Reader. Custom agents cannot remediate or publish issues, labels, comments, or pull requests. No writing schedule is enabled.
      
      
      Explicit operator changes
      Provisioning, image publishing, faults, recovery, sample issues, and teardown are separate decisions. Public HTTPS endpoints have no authentication; use synthetic data only. Azure resources and builds are billable.
      
    
      
    
      You need .NET 10, Node 24, Python, Azure CLI/azd, deployment and RBAC permissions, and Azure SRE Agent availability. GitHub is optional. Preview APIs and live onboarding are not validated by offline tests; OOM and alert delivery are not guaranteed. Recovery loses in-memory carts/orders.
