      How it works
      
      
      One operating model for SRE Agent.
      
      
      Whether Azure SRE Agent is syncing a module, patching a fleet or chasing a 5xx spike, it follows the same loop. SRE Agent takes on the repetitive work; change still goes through people and pipelines.
      
      
        
        
      1. Trigger
        A request, a schedule, a new release, a lifecycle notice or an alert starts the run.
        2. 
        
      2. Analyze
        SRE Agent discovers, compares and validates with least-privilege, read-only access.
        3. 
        
      3. Approve
        A pull request, change or plan with labeled evidence waits for a human decision.
        4. 
        
      4. Apply
        Deterministic pipelines apply the approved change and verify the result.
        5.
