Why it matters

The problem it solves.

Many widely used VM size series are End of Life, with retirement dates from 2028 to 2029, capacity growth restrictions already in place and no new reserved instances. Each VM needs a dozen checks, and a spreadsheet is out of date as soon as it's finished.

  • A plan for every VM

    Each VM and scale set gets a disposition record: the path, a target family and size class, the evidence, and what's still to check.

  • Checked before it lands

    Quota headroom, zone availability and Azure Policy are checked first, because an old allowed-size policy can deny every proposed size.

  • Always current

    A weekly scan reports new VMs in scope, quota changes, expiring reservations and progress, instead of a one-time snapshot.

  • Read-only until approved

    Analysis never changes a resource. Pilot resizes run in one resource group, one approved command at a time.

How it works

From trigger to approved change.

The same operating model as every use case in the showcase, applied to Azure VM Lifecycle Transition.

  1. Trigger

    An on-demand assessment, or the weekly scheduled scan

  2. Analyze

    Finds and profiles every VM on an End of Life series, then recommends and validates a target

  3. Approve

    Owners review each record; every pilot resize command needs its own approval

  4. Apply

    Pilot VMs are resized and verified, with rollback if a check fails

      Safety
      
      
      Built to keep people in control.
      
      
      
      
        
      Read-only by design
      • Analysis and the weekly scan run at the Reader permission level
      • Never buys reservations, creates capacity reservations or submits quota requests: it drafts
      • An evidence gate blocks final sizes, prices and capacity guarantees in reports
      
        
      A human decides
      • Pilot resizes run in Review mode, one approved command at a time
      • Writes outside the pilot resource group are blocked by a hook
      • Vendor appliances, SAP-gated workloads and domain controllers are never automated

      Is it for you?
      
      
      Who it helps and what it takes.
      
      
      
      
        
      Who it's for
      • Infrastructure and operations teams with VMs on End of Life series
      • Architects and migration partners planning transition waves
      • Azure SRE Agent practitioners looking for a change scenario that starts read-only
      
        
      What you need
      • Azure SRE Agent in your tenant
      • Reader on the in-scope resource groups, plus subscription-level reads for quota, sizes and Azure Policy
      • VM insights for utilization (optional, otherwise reported as unknown)
      • Virtual Machine Contributor on one pilot resource group, for Phase 3 only
