Why it matters

The problem it solves.

Architecture diagrams are drawn by hand and drift as soon as the workload changes. Reviews against the Well-Architected Framework come late, and assumptions often end up presented as deployed reality.

  • Evidence, not guesses

    Every resource and relationship is labeled observed, inferred or proposed, with confidence and rationale.

  • One complete package

    A report, an editable diagram, validation findings and a WAF review, all built from the same model.

  • Drift made visible

    Fresh read-only discovery is compared with the approved baseline and proposed as a reviewed update.

  • People stay in control

    GitHub sync and any IaC draft need explicit approval. The agent never mutates Azure or merges.

How it works

From trigger to approved change.

The same operating model as every use case in the showcase, applied to Architecture Writer.

  1. Trigger

    An on-demand request or a scheduled drift check for a defined scope

  2. Analyze

    Discovers Azure read-only, models boundaries and flows, validates the result

  3. Approve

    An owner approves the artifacts before a draft pull request is opened

  4. Apply

    A human merges the pull request, which becomes the next baseline

      Safety
      
      
      Built to keep people in control.
      
      
      
      
        
      Read-only by design
      • Uses least-privilege, read-only Azure and repository access
      • Never mutates Azure, runs remediation or deploys Terraform or Bicep
      • Never fabricates resources, flows, redundancy or recovery claims
      
        
      A human decides
      • Explicit approval before drafting IaC or syncing to GitHub
      • A human reviews and merges every pull request
      • The agent never pushes to a protected branch

      Is it for you?
      
      
      Who it helps and what it takes.
      
      
      
      
        
      Who it's for
      • Cloud architects
      • Platform engineers
      • SRE teams that need current architecture documentation
      
        
      What you need
      • A defined scope, audience and purpose
      • Read-only Azure inventory access, such as Azure Resource Graph
      • A diagram capability for SVG, Mermaid or draw.io
      • An approved GitHub repository and branch policy
      
      
      
      
      The value
      Keeps architecture baselines current while gating GitHub sync and optional IaC behind human approval
