Why it matters

The problem it solves.

Teams rarely get to practice incident response end to end before a real outage. Without a safe rehearsal, crash-loop diagnosis, rollback decisions and approval boundaries are learned under pressure, on production.

  • A realistic, scoped failure

    A runnable Container Apps demo injects one crash-looping revision into a dedicated demo app.

  • Evidence-backed investigation

    Azure SRE Agent correlates revisions, traffic, logs and metrics read-only and proposes a rollback.

  • Every step is a human decision

    Provisioning, fault injection, rollback and teardown are separate, explicitly approved steps.

  • Verified recovery

    Recovery restores the captured baseline traffic and retires only the injected revision.

How it works

From trigger to approved change.

The same operating model as every use case in the showcase, applied to Azure SRE Incident Response (Reactive).

  1. Trigger

    An operator approves simulated downtime and injects a failing revision

  2. Analyze

    The agent correlates revisions, traffic, logs and metrics read-only

  3. Approve

    The operator reviews the proposed rollback and approves recovery

  4. Apply

    The operator's script restores baseline traffic and verifies health
