Why it matters

The problem it solves.

Retirement notices, runtime end-of-support dates and service transitions are scattered across inventory, lifecycle documentation, Service Health and ownership records. Teams miss them until a deadline becomes an incident.

  • Deadlines before they bite

    Confirmed retirement and end-of-support dates are ranked in one queue, each tied to a resource and a Microsoft Learn source.

  • Evidence, not guesses

    Verified facts are kept apart from items that need code validation, and gaps in Service Health coverage are called out.

  • Ready to communicate

    A Subscription Context column lists the subscription and its direct Owners so the right people hear about each deadline.

  • Read-only for Azure

    The workflow never migrates, restarts, deletes or scales resources. Every migration stays a human decision.

How it works

From trigger to approved change.

The same operating model as every use case in the showcase, applied to Azure Retirement Readiness.

  1. Trigger

    An on-demand request, or a weekly refresh you explicitly asked for

  2. Analyze

    Inventories the subscription and checks lifecycle dates and Service Health

  3. Approve

    Service owners review the prioritized queue and phased migration plan

  4. Apply

    Teams run each migration with validation, canary deployment and rollback
